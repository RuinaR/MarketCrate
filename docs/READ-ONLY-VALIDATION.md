# 사용자 직접 Steam 읽기 검증 — 0.13 부분 관측 / 0.14 재확인

## 0.18 일반 사용자 확인 경로

정식 Release의 전용 '연결 자가검증' 페이지와 범위 체크박스는 제거했다. 기존 검사는 개발 회귀 구성에 남긴다. 일반 앱에서는 계정 연결/복원→보관함 게임 선택→갱신, 판매 중→판매목록만 조회, 보관함 판매 계획→지갑 통화만 조회/지갑·수수료만 조회, 품목 선택→시세 갱신을 직접 사용한다. 문제 해결→현재 오류/관련 작업→범위 검토→진단 ZIP으로 증거를 내보낸다.

사용자 실제0.17 복원 성공·목록8·명시적 빈CS2·KRW wallet/legacy5필드를 보존한다. fee200 HtmlMarket은 실패, 품목 없는 호가/이력/이미지는 미검증이다. 새 resolver가 실제 계정에서 어떤 모드를 관측하는지는 새 버전에서 **지갑·수수료 조회1회**로 확인해야 한다. 실패하면 반복 요청/거래 없이 정제 ZIP만 제공한다. 원본 HTML/Auth/QR/계정정보는 전달하지 않는다.

성공해도 실제 판매는 자동 활성화되지 않는다. 공식 Steam 판매 UI의 최소·일반·다른 가격3개를 직접 보고4금액을 비교한다. 공식 화면에 개별 수수료가 없으면 추측하지 말고 해당 비교는 미검증으로 둔다. 첫 실판매/복수/다중 게임/취소·재가격 검증은 기존 사용자 별도 절차를 따른다.


## 16차 — 사용자 직접 로그인 유지 확인

1. 새0.17.0 portable을 별도 폴더에 풀고 직접 실행한다. 기존 진단·SQLite/저널/설정/롤백을 삭제하지 않는다.
2. 계정 연결에서 위험 안내와 **로그인 상태 유지**를 선택한 뒤 QR을 공식 Steam 앱에서 직접 승인한다. 인증 완료와 암호화 저장 완료가 모두 표시되는지 확인한다.
3. 로그아웃 버튼을 누르지 말고 앱을 종료→재실행한다. 정상 저장 파일이 있을 때 인증 복원을 한 번만 시도하고 보관함/목록/거래는 자동 실행하지 않아야 한다. 실패/만료면 재인증 안내를 확인한다.

5. 오류 시 해당 작업 진단 ZIP만 검토·내보낸다. Auth 폴더/암호화 blob/토큰/쿠키/QR 원본은 보내지 않는다. 차단 후 재시작을 반복하지 말고 저장 정보 삭제→새 QR을 선택한다.
6. 명시적 로그아웃 후 재실행에는 QR이 다시 필요해야 한다. '이 PC의 저장 로그인 삭제'는 로컬만 삭제하며 현재 메모리 연결은 별도 로그아웃까지 유지될 수 있다. 서버 철회를 완료했다고 표시하지 않는다.

지원/실패/저장 파일·보안 한계·자동 갱신 미지원의 상세는 SESSION-PERSISTENCE.md 참조. Codex는 이 절차를 실제 계정/GUI에서 실행하지 않는다.

## 0.16.1 최소 사용자 재검증 — 수수료 범위

1. 새 LiveOnly portable을 별도 폴더에 풀어 직접 실행한다. 기존 DB/저널/로그/설정/롤백본은 유지한다.
2. 앱의 QR을 사용자 본인이 승인하고 계정 연결 → 자가검증에서 **지갑·수수료만** 선택·승인하여 한 번 실행한다. 실제 거래는 OFF 유지한다.
3. 성공/실패/차단의 상세 분류와 시각을 확인한다. 장터 HTML/분류불가/로그인 폼/보안 위젯을 구분한다. 호출 제한·인증/보안 요구는 우회하거나 반복 재시도하지 않는다.
4. 실패 시 이 작업의 진단 ZIP을 검토·내보낸다. HTML·쿠키·토큰·QR 원본을 별도로 보내지 않는다. 새 Event3005로 매체/본문 형식을 대조할 수 있다.
5. 실제 fee schedule 조회가 성공했을 때만 고급 설정의 '공식 장터 수수료 비교'에서 같은 게임/통화의 판매자·구매자 **단가**를 공식 화면과 비교한다. KRW 원 / USD 달러 입력. 불일치면 판매하지 않는다. 수수료 미확인 시 비교 버튼은 비활성화되고 이유를 표시한다. 수동 입력을 자동 가격·권한으로 채택하지 않는다.

Fees HTML을 기본5%/10%나 다른 도우미의 USD 계산식으로 덮어쓰지 않는다. 실제 등록·취소·재가격/KRW fee/스택/Guard 게시 대조의 실계정 검증은 별도 사용자 단계이며 이번 Codex 작업에서는 실행하지 않았다.

Codex는 실행하지 않았다. 실제 계정은 사용자만 프로그램 안에서 직접 연결한다. 0.14 관측은 세션·목록8·명시자산0·Wallet302 OtherRedirect다. 새버전이 모든302를 우회하지 않는다.

3. 읽기계약이 실제로 충족되고 위험을 이해한 사용자가 원할 때만 고급설정의 위험동의/‘실제 거래’ 입력→이번세션 활성화(읽기preflight). 이는 Valve 허가·LIVE_VERIFIED가 아니다. 기존등록이 없는 계정의 첫bootstrap/스택은 현재 지원제한이며 우회하지 않는다.
4. 활성화가 성공한 경우에만 가치가 낮고 잃어도 무방한 **비스택 단일아이템1개**를 선택한다. 호가갱신→가격/수량/구매자결제·Steam/게임fee·실수령·시각을 직접확인→전체판매등록 한 번. 자동저가변경 없음. 공식 Steam 모바일 앱에서 사용자가 직접 승인하고 앱에서 명시적새로조회로 게시를 대조한다. 승인대기는 완료가 아니다.
5. 불명/ID누락/예상금액불일치/미게시/제한이면 즉시 후속시험 중단. 재클릭·새키재전송 금지, 저널과 진단 보존. 단일항목의 listingID·가격/수량·게시증거가 확인된 뒤에만 별도 단계로 동일상품 복수비스택→다중상품→scope별검증한 다중게임을 시험한다. 스택 capability는 실서버 근거 전 계속OFF.
6. 취소는 별도 최종검토 후 실행·수동대조한다. 반환이 확인되지 않으면 재등록/재가격을 시험하지 않는다. 동일단일자산 반환의 인과증거가 있는 경우에만 새가격을 다시 승인한다. ID변경/합산/스택증가/오래된호가는 Unknown/새검토로 중단한다. 로그아웃·동의해제·세션만료 후 새활성화 필요.

이 절차는 정책·계정위험을 없애지 않는다. 공식 장터에서 직접 관리하는 대체흐름은 앱 핵심 일괄등록 완료로 판정하지 않는다.

실패가 남으면 OperationId로 진단 검색→포함범위 직접검토→로컬 ZIP 공유. 필요한 증거는 버전/커밋·고정endpoint/HTTP상태·안전오류코드·redirect분류·wallet shape/필드존재·inventory total/페이지/모순분류다. 인증응답·QR·쿠키·토큰·계정ID·원본HTML/JSON은 공유하지 않는다. Codex는 실계정 연결/자가검증을 실행하지 않았다.

## 0.13.0 최소 사용자 절차

이 절차는 **사용자가 직접 선택하는 로그인·읽기**이며 Codex는 실행하지 않았다. 기존 브라우저 로그인으로 앱이 자동 연결되지 않는다. 앱 QR을 원치 않으면 공식 장터 직접 관리만 이용할 수 있다. OpenID 신원 확인은 앱 장터 세션이 아니다.

1. 새 portable 폴더의 EXE를 인자 없이 직접 실행한다. 기존 사용자별 DB/저널을 삭제하지 않는다. 계정 연결에서 위험을 확인하고 원하는 경우에만 QR 시작→공식 모바일 앱에서 사용자 직접 승인→모바일 승인 상태 확인. QR·인증정보는 공유하지 않는다.
2. **읽기 전용 자가검증 화면**으로 이동한다. 우선 판매목록/선택 게임 보관함/지갑/fee 등 필요한 범위만 선택한다. 모든 범위는 기본OFF, 이번 실행 승인에 체크한 뒤 실행한다. fee는 지갑 선택·성공이 필요하다. 거래 제한을 해제하거나 거래 활성화를 켜지 않는다.
3. 목록은 첫 페이지(요청 count100), 보관함은 선택한 game/context 첫 페이지(count1000)만 요청한다. 출력된 자산 수는 관측 페이지 수이며 서버 활성 총계와 전체 페이지 검증을 구분한다. 첫 페이지 성공이 전체 보관함 정상/완전 조회를 뜻하지 않는다.
4. 호가·이력·이미지까지 확인하려면 보관함 화면에서 본인이 확인할 자산 **하나만** 선택한 뒤 자가검증에서 원하는 추가 범위와 이번 승인을 선택한다. 여러 품목/품목 없음/확인할 이미지 없음이면 해당 검사는 미검증·무요청이다. 이미지 캐시 또는 무인증 CDN 바이트/픽셀 상한 검사이며 실제 표시·수집시각은 별도다.
