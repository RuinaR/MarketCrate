## 0.16.0 사용자 최소 확인

새 ZIP을 별도 폴더에 풀어 실행하면 실제 Steam 관리/진단만 표시되어야 한다. Mock 탭·가짜 품목·Mock 배치 버튼이 없어야 한다. 기존 DB/저널/진단 ZIP을 삭제하지 않는다. 실제 Release는 격리 Mock 인자를 받지 않는다.

사용자가 직접 QR 승인 후 자가검증에서 지갑만 선택해 이번 조회를 한 번 승인한다. 정상 자격 확인이 요청되면 서버의 확인 응답과 고정 Market 복귀를 처리한다. 자격 거절·로그인·401/403/429·CAPTCHA·순환·알 수 없는 이동은 우회하지 않는다. 통화/단위/fee가 불완전하면 실제 가격/거래를 생성하지 않는다.

지갑 성공이 표시되더라도 최소 단위/증분과 게임별 수수료 계약은 별도 확인한다. 아직 실패하면 작업 상세→현재 작업 진단→검토된 ZIP으로 원인을 확인한다. 원본 URL/인증정보를 수집하지 않는다. Codex는 사용자 세션이나 거래를 실행하지 않았다. 실거래 기본 OFF와 기존 단계별 검증 조건은 유지한다.

## 0.15.0 최소 절차와 단계별 실제 거래 시험

Codex는 실행하지 않았다. 실제 계정은 사용자만 프로그램 안에서 직접 연결한다. 0.14 관측은 세션·목록8·명시자산0·Wallet302 OtherRedirect다. 새버전이 모든302를 우회하지 않는다.

1. 새 portable을 별도폴더에 풀고 기존 DB/저널을 보존한다. 직접 QR 승인 후 목록/선택게임 보관함/지갑/fee 최소범위를 한 번 승인해 조회한다. 정상 Market/언어 이동은 한 번만 처리한다. 인증요구·403/429/CAPTCHA·알 수 없는302면 중단한다.
2. 자산0이면 판매대상을 만들지 않는다. wallet 통화·명시적최소가격/증분·게임fee가 없거나 기존 같은게임등록 fee 비교가 불가능하면 거래활성화 불가다. 값을 수동으로 만들어 넣지 않는다. 실패 작업의 정제ZIP만 직접검토해 공유한다.
3. 읽기계약이 실제로 충족되고 위험을 이해한 사용자가 원할 때만 고급설정의 위험동의/‘실제 거래’ 입력→이번세션 활성화(읽기preflight). 이는 Valve 허가·LIVE_VERIFIED가 아니다. 기존등록이 없는 계정의 첫bootstrap/스택은 현재 지원제한이며 우회하지 않는다.
4. 활성화가 성공한 경우에만 가치가 낮고 잃어도 무방한 **비스택 단일아이템1개**를 선택한다. 호가갱신→가격/수량/구매자결제·Steam/게임fee·실수령·시각을 직접확인→전체판매등록 한 번. 자동저가변경 없음. 공식 Steam 모바일 앱에서 사용자가 직접 승인하고 앱에서 명시적새로조회로 게시를 대조한다. 승인대기는 완료가 아니다.
5. 불명/ID누락/예상금액불일치/미게시/제한이면 즉시 후속시험 중단. 재클릭·새키재전송 금지, 저널과 진단 보존. 단일항목의 listingID·가격/수량·게시증거가 확인된 뒤에만 별도 단계로 동일상품 복수비스택→다중상품→scope별검증한 다중게임을 시험한다. 스택 capability는 실서버 근거 전 계속OFF.
6. 취소는 별도 최종검토 후 실행·수동대조한다. 반환이 확인되지 않으면 재등록/재가격을 시험하지 않는다. 동일단일자산 반환의 인과증거가 있는 경우에만 새가격을 다시 승인한다. ID변경/합산/스택증가/오래된호가는 Unknown/새검토로 중단한다. 로그아웃·동의해제·세션만료 후 새활성화 필요.

이 절차는 정책·계정위험을 없애지 않는다. 공식 장터에서 직접 관리하는 대체흐름은 앱 핵심 일괄등록 완료로 판정하지 않는다.

## 0.14.0 — 부분 관측 후 최소 재확인

0.13 사용자 관측은 세션기록·목록첫8/활성8·CS2첫0·지갑인증확인차단 및 후속차단이다. 전체목록 지원·정상빈보관함·지갑실패 원인은 미확정이다. 아래0.13 절차는 이력이다.

새 portable을 별도 폴더에 풀어 사용자가 직접 실행한다. 기존 DB/설정/저널을 삭제하지 않는다. 원하면 QR을 직접 승인하고 자가검증에서 목록·선택게임보관함·지갑의 최소 범위부터 이번 실행을 명시 승인한다. 목록/보관함은 첫페이지만 관측한다. 자산0은 명시적 success/total0/추가페이지 없음일 때만 정상빈으로 표시한다.

상단 요약과 각 행 **작업 상세 보기**를 확인한다. Authentication=세션재확인, Authorization=해당조회권한제한, AccessRestricted/RateLimited=중단, ContractMismatch/Parsing=계약문제, Unsupported=미지원, Empty=검증된빈페이지. 명시적401/403/429/CAPTCHA를 우회하거나 반복요청하지 않는다. 통화만 확인된 지갑은 가격단위/증분·실제수수료계약 미검증이다. 선택자산 없으면 호가/이력/이미지는 미검증·무요청이다.

실패가 남으면 OperationId로 진단 검색→포함범위 직접검토→로컬 ZIP 공유. 필요한 증거는 버전/커밋·고정endpoint/HTTP상태·안전오류코드·redirect분류·wallet shape/필드존재·inventory total/페이지/모순분류다. 인증응답·QR·쿠키·토큰·계정ID·원본HTML/JSON은 공유하지 않는다. Codex는 실계정 연결/자가검증을 실행하지 않았다.

## 0.13.0 최소 사용자 절차

이 절차는 **사용자가 직접 선택하는 로그인·읽기**이며 Codex는 실행하지 않았다. 기존 브라우저 로그인으로 앱이 자동 연결되지 않는다. 앱 QR을 원치 않으면 공식 장터 직접 관리만 이용할 수 있다. OpenID 신원 확인은 앱 장터 세션이 아니다.

1. 새 portable 폴더의 EXE를 인자 없이 직접 실행한다. 기존 사용자별 DB/저널을 삭제하지 않는다. 계정 연결에서 위험을 확인하고 원하는 경우에만 QR 시작→공식 모바일 앱에서 사용자 직접 승인→모바일 승인 상태 확인. QR·인증정보는 공유하지 않는다.
2. **읽기 전용 자가검증 화면**으로 이동한다. 우선 판매목록/선택 게임 보관함/지갑/fee 등 필요한 범위만 선택한다. 모든 범위는 기본OFF, 이번 실행 승인에 체크한 뒤 실행한다. fee는 지갑 선택·성공이 필요하다. 거래 제한을 해제하거나 거래 활성화를 켜지 않는다.
3. 목록은 첫 페이지(요청 count100), 보관함은 선택한 game/context 첫 페이지(count1000)만 요청한다. 출력된 자산 수는 관측 페이지 수이며 서버 활성 총계와 전체 페이지 검증을 구분한다. 첫 페이지 성공이 전체 보관함 정상/완전 조회를 뜻하지 않는다.
4. 호가·이력·이미지까지 확인하려면 보관함 화면에서 본인이 확인할 자산 **하나만** 선택한 뒤 자가검증에서 원하는 추가 범위와 이번 승인을 선택한다. 여러 품목/품목 없음/확인할 이미지 없음이면 해당 검사는 미검증·무요청이다. 이미지 캐시 또는 무인증 CDN 바이트/픽셀 상한 검사이며 실제 표시·수집시각은 별도다.
5. 결과의 성공(관측 범위)/실패/차단/미지원/미검증/중단과 다음 조치를 확인한다. UTC/KST는 검사 시각이다. 한 품목의 fee 비율 대조가 일치해도 실제 판매 수수료 계약 검증은 아니다. 서버 통화/시세·fee 불일치는 실패로 남는다. QR 기록의 세션 존재와 현재 각 서버 조회 권한을 혼동하지 않는다.
6. 401/인증 요구는 재로그인 필요,403/429/CAPTCHA/안전 차단은 나머지 요청을 중단한다. 우회·반복 요청을 하지 않는다. 각 행의 작업ID를 진단 화면에서 검색→포함 범위 검토→동의 후 로컬 ZIP으로 저장한다. ZIP을 직접 검토해 공유하며 QR·쿠키·토큰·원본 응답은 보내지 않는다. 실제 판매·취소·재가격·Guard 판매 승인은 이번 검증 범위가 아니다.

범위/게임/품목 변경은 실행 전 승인을 무효화하고 실행 시 plan은 고정된다. 실행 중 범위 입력은 잠기지만 미전송 작업 중단은 사용할 수 있다. 결과는 앱/VM 세션의 진단 자료이며 전체 목록·선택·수량·거래 저널을 덮어쓰지 않는다. 자동 시작·백그라운드 검사·자동 재시도·자동 ZIP 업로드가 없다. 종료/로그아웃 시 결과·실행 승인을 정리한다.

13차 전달 파일: `artifacts/MarketCrate-0.13.0-stage13-dd7e276-win-x64.zip`(78.31MiB,412파일), 버전0.13.0+dd7e276, 정적 검사 PASS/실제 실행 미검증. SHA256 `2B76B0ACB3440CCBA5F2C2364AAD46BA458D10E89E329A8456400A0ED83BD7C8`.

이 절차는 사용자가 직접 선택하는 비공식 로그인·읽기 검증이다. Codex가 계정에 접속하거나 QR·토큰·쿠키를 전달받는 절차가 아니다. 실제 등록·취소·재가격·모바일 판매 승인은 포함하지 않는다. 읽기도 계정 제재 위험이 없다고 보장하지 않으며, 동의 버튼은 Valve의 허가를 뜻하지 않는다.

## 최소 확인 경로

1. 새 self-contained 폴더의 `MarketCrate.App.exe`를 **인자 없이** 직접 실행한다. 기존 사용자 데이터는 지우거나 옮기지 않는다. `--isolated-qa`는 읽기가 차단된 별도 모드다. 현재 빌드의 물리 GUI는 사용자가 추가 확인해야 한다.
2. Steam 작업 공간 → 계정 연결에서 위험 안내를 읽고 직접 동의한 경우에만 QR 시작을 누른다. 본인의 공식 Steam 앱에서 계정과 요청 내용을 확인한 뒤 직접 인증한다. `모바일 승인 상태 확인`은 명시적 클릭이며 자동 폴링하지 않는다. 서버가 QR을 바꾸면 새 그림이 표시된다. 만료·거절·네트워크 오류면 상태와 작업 ID만 기록하고 제한/CAPTCHA를 우회하지 않는다. QR·스크린샷·토큰을 공유하지 않는다.
3. 연결 후 먼저 `판매목록만 조회`를 누른다. 공식 장터의 목록과 개수·가격·수량·승인 대기 상태를 사람이 비교한다. 이 버튼은 보관함이나 지갑 조회 성공에 의존하지 않는다. 새 게임이 관측되면 카탈로그에 반영한다. 다음으로 알고 있는 게임 하나를 선택하고(직접 추가는 고급 설정) 보관함을 갱신한다. 인증 상태와 조회 결과를 별도로 확인한다. 파싱/404 실패는 다른 조회를 막지 않으며,401은 재로그인,403/429/CAPTCHA는 요청 중단이다. 제한을 지우려고 재로그인·반복 요청하지 않는다. 게임 전체를 무차별 조회하지 않는다. 이미지 로딩은 별도 선택 사항이다.
4. `지갑·수수료만 조회`로 KRW/USD·최소 단위·증분을 확인한다. 판매 가능 자산 하나를 선택해 수량을 지정하고 즉시거래가능가로 시세를 갱신한다. 최종 검토에서 가격대별 수량, 잔량 부족, 구매자 금액·수수료·실수령액·수집 시각을 확인한다. **전체 판매등록은 누르지 않는다.** 기본 차단 상태를 유지하며 계약이 불확실한 가격을 확정값으로 판단하지 않는다. 중앙값 추정은 정확한 평균이 아니다.
5. 로그아웃 시 QR/계정 데이터가 지워지고 다시 사용자 QR 인증으로 연결되는지 확인한다. 인증 만료가 관측되면 이전 표가 최신 데이터로 오인되지 않고 새 검토가 비활성인지 확인한다. 외부 서버 장애를 일부러 만들거나 호스트 네트워크 설정을 바꾸지 않는다. 취소·재가격은 **검토만** 확인하고 실제 요청은 하지 않는다.

필요한 증거는 빌드 commit, 작업 시각, 고정 오류 코드, OperationId, 비교 결과다. 실패하면 `현재 Steam 작업의 진단 보기` → 해당 작업 필터/갱신 → ZIP 포함 범위 검토 → 확인 후 로컬 내보내기를 사용한다. 원본 HTTP·계정 ID·아이템 ID·비밀값을 따로 수집하지 않는다. `ReadContract`는 파싱한 건수/통화/endpoint와 합성 여부만 남기므로 이것만으로 서버 계약 전체를 인증할 수 없다.
