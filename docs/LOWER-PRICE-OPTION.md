## 0.20.21 잔량 부족의 수동 가격

잔량이 부족한 행은 자동 하향 기준이 없습니다. 유효한 가격을 직접 입력하면 수수료/실수령/전체 합계가 갱신되고 같은 최종 승인으로 제출됩니다. 하향 비교만 생략하며 항목을 배치에서 제외하지 않습니다. 정상 조회된 빈 호가만 명시적 수동 가격을 허용하며 조회 실패와 혼동하지 않습니다.

# 즉시거래가능가보다 한 단계 낮게 — 0.20.20

기본값은 OFF이며 기존 즉시거래가능가를 유지한다. 보관함의 판매 계획 또는 판매 중 목록에서 **즉시거래가능가보다 한 단계 낮게**를 직접 선택하면 새 검토에 적용한다. 로그인/재연결/앱 재시작으로 자동 선택하지 않으며 과거 승인 가격을 변경하지 않는다. 실제 체결 보장이나 자동 재가격 기능이 아니다.

## 한 단계의 의미

1. 기존 방식대로 같은 상품의 구매주문 잔량을 공유해 수량을 가격 단계에 배정한다.
2. 각 배정 호가를 현재 서버 수수료·최소/증분에 맞는 기본 유효 구매자 가격으로 계산한다.
3. 그 기본 가격보다 **엄격히 낮으면서 가장 가까운 도달 가능한 구매자 총액**을 찾는다. 원/센트1을 무조건 빼서 전송하지 않는다.
4. 해당 가격의 판매자 수령액·Steam/게임 수수료를 역산한다. 더 낮출 수 없는 최저 유효 가격이면 해당 가격을 유지한다. 검토에 최저가 유지와 수수료·실수령 감소0을 명시한다. 잘못된 가격/계약을 예외 처리로 성공 대체하거나 항목을 조용히 제외하지 않는다.

구현: SteamFeeSchedule.LowerOrMinimumBuyerPrice는 최저 유효 가격이면 그대로 반환하고, 그 밖에는 PreviousValidBuyerPrice를 사용한다. PreviousValidBuyerPrice는 정확한 기본 구매자 가격을 확인한 뒤 그보다 작은 목표에서 기존 FromBuyer(..., false) 역산을 사용한다. 통화별 wire/표시 단위, fee gap, 최소/증분과 Publisher0 계약을 그대로 존중한다.

## 최종 검토와 승인

- 행별 기본/변경 구매자 가격, Steam 수수료, 게임 수수료, 실수령을 표시한다.
- 해당 수량의 실수령 감소액/비율과 전체 합계 비교를 표시한다. 수수료 자체도 줄 수 있으므로 기존 수수료를 고정 차감하지 않는다.
- 수동 가격 수정은 현재 검토 안에서 가능하며 실제 입력 가격으로 비교와 전체 합계를 즉시 갱신한다. 기본보다 높게 고치면 ‘감소’로 꾸미지 않고 증가로 표시한다.
- 옵션은 작업 중/검토 중 변경하지 못한다. 돌아가기 → 옵션 변경 → 새 검토가 필요하며 이전 수동 가격을 새 기준으로 몰래 재사용하지 않는다.
- **전체 판매등록 한 번**으로 현재 검토의 모든 가격·수량을 불변 snapshot으로 고정해 기존 coordinator가 직렬 제출한다. 옵션 선택이나 검토 생성은 판매 요청이 아니다.
- 제출 전 서버 보관함/계정/수수료/가격·orderbook fingerprint 재검증을 유지한다. 자료 변경 시 자동으로 더 낮추지 않고 기존 승인을 폐기한다. 부분 성공/Guard/Unknown/Ready·저널·중복 방지·자동 재전송 금지는 같다.

판매 중 목록의 ‘선택 전체 재등록 가격 검토’에도 적용한다. 전체 제안 계산이 가능해야 취소/재가격 검토를 연다. 소유 등록의 확정 취소·반환을 검증할 수 있는 경로는 한 관리 승인으로 직렬 재등록하고, 외부 등록/불명 반환은 기존 취소 후 새 대상 검토 및 새 최종 승인을 요구한다. 보존된 과거 계획의 가격은 옵션을 켰다는 이유로 자동 변경하지 않는다.

실제 통화/수수료/스택 계약이 불명하면 기존처럼 전송을 차단한다. 스택의 여러 가격 요청을 새로 허용하거나 서버 보호를 해제하지 않는다. 할인한다고 FX·실제 주문 적격·잔고·주문장 시점 차이가 없어지지 않으며 즉시 체결은 보장하지 않는다. 공식 Steam Guard는 사용자가 직접 승인한다.
