# MarketCrate — 제품 정의서 (2026-10-28)

## 현재 기준 —0.20.13

일반 Release는 실제 Steam 데이터 전용이다. 개발 Mock/합성 테스트는 출하에서 제외한다. 사용자0.17의 QR/Community·로그인 복원·목록8건·명시적 빈CS2·KRW 지갑 관측과 이후 버전의 합성 검증을 구분한다. 최초75개 ID는 유지하며 현재 판정47 COMPLETE/16 PARTIAL/0 MISSING/3 BLOCKED/9 UNVERIFIED다.

단일 최종 승인 전체 판매등록 목표를 유지한다. 이번 안정화 범위는 승인 snapshot 불변성, 계정별 저널 분리, 취소 후 현재 보유 자산의 새 검토, 보안 런타임·의존성·구/신 SQLite 호환성이다. 검증 범위와 남은 차단 조건은 RELEASE-READINESS를 따른다. 실계정 수수료/스택/실판매·물리 GUI의 증거는 부족하며 전 제품 완료 또는 RELEASE_READY를 선언하지 않는다. 아래 버전별 기록은 당시 상태다.


## 10차 제품 범위

실제 Steam 계정 연결과 관리가 우선이며 최종 단일 승인 전체 실등록 목표는 유지한다. 즉시거래가능가 용어/안정 저장키, QR 회전, 독립 목록·fee 조회, 사용자 계약 진단, 공식 장터 수동 대체 경로를 보완했다. 사용자9차 GUI 기본7개는 보고된 범위만 인정한다. READ_ONLY_READY/LIVE_CONTRACT_READY/LIVE_READY/RELEASE_READY는 아직 부여하지 않는다. 현재 실계정 테스트 없이 등록·취소를 활성화하지 않는다. 구체적 구현/검증 범위는 CURRENT-STATUS와 READ-ONLY-VALIDATION을 따른다.

## 7차 범위

기존 75개 ID를 유지하며 이미지/수동·관측 context 카탈로그/정확 평균과 구분된 추정 지표를 실제 코드/UI/합성 계약/비표시 WPF로 연결했다. 단일 최종 승인 전체 실제 등록 목표와 기본 IntegrationBlocked 유지. 현재 로컬 기준 47 COMPLETE/15 PARTIAL/0 MISSING/4 BLOCKED/9 UNVERIFIED이며 실계정 출시 준비 완료를 뜻하지 않는다. 상세 기준은 REQUIREMENTS-TRACEABILITY/QA-MATRIX.

## 5차 범위 (최신)

- 실험 어댑터를 사용자 시작 QR/읽기/선택/가격 검토/결과·수동 대조/관리 UI에 연결한다. Mock과 출처·상태를 분리하며 실제 거래 기본 차단은 유지한다.
- KRW/USD 정수/wire·서버 fee profile, 공유 호가·스택 예약과 반환 증거, 감사 이력·재시작·재가격 의도를 구현하고 합성 서버로 종단 검증한다. 실제 계정 지원/제품 출시 완료를 의미하지 않는다.
- 남은 제한: Valve 정책 근거 및 실계정 인증/거래/수수료/스택 검증, 게임 scope 자동 발견, ID 변경/미인과 후보 확정, stale 재가격 revision·live 확정 실패 retry, 실사용 설치/보안 감사. 실제 단일 승인 전체 등록 목표는 계속 유지한다.

## 4차 범위 (최신)

- 실제 Steam 조회/판매/취소의 비공식 HTTP 어댑터 소스를 기본 비활성으로 추가하고 합성 계약 검증한다. 현재 WPF는 Mock이며 실계정 제품 흐름 완료가 아니다.
- 별도 QR 인증 프로토콜/메모리 세션·통화/응답 검증·영구 의도·서버 대조 경계를 구현한다. 최종 단일 승인 전체 실등록 목표와 타 앱 비간섭은 유지한다.
- 미완성: QR/실계정 UI, 원화 실등록·스택 분배·전체 판매 자격/보류 조건, 등록ID 없는 결과 대조, 확정 취소/실제 재가격·실계정 시험/배포 감사. 비공식 제재 위험과 인증 보안 위험은 별도 공개한다.

## 제품 목적
Windows에서 사용자의 여러 Steam 게임 보관함과 Community Market 판매 현황을 한 곳에서 확인하고, 안전한 일괄 판매 준비/가격 검토와 **한 번의 최종 승인으로 전체 실제 등록**을 목표로 하는 도구. 이름 `MarketCrate`는 가칭이며 Steam 공식 앱이 아님.

## 3차 구현 판정 (2026-10-28)
- 개별 가격/수수료·실수령/잔량 부족/수동 가격 규칙을 포함한 최종 Mock 검토와 판매 전체 선택·가격 변경·확정 실패 수동 재시도를 구현했다.
- SQLite v2 보존 이관·변경 행 저장·유한 구조화 진단·소유 headless 자식 종료 후 복구 및 Release 산출물 생성을 검증했다. 실제 GUI 실행·설치/배포·하드웨어 전원 차단은 검증하지 않았다.
- 실연동 조사 결과 publisher/앱/secure server 제한을 개인용 판매 권한으로 사용할 수 없었고 허용된 일반 실등록 경로는 미확보다. 필수 단일 승인 실등록 목표는 **LIVE_INTEGRATION_BLOCKED**이며 Mock 성공으로 대체하지 않는다.

## 2차 구현 판정 (2026-10-28)
- 창 없는 STA 자체 렌더·바인딩·상태 검증, 대량 카드/목록 가상화, SQLite 합성 데이터·설정·저널 영속화, 판매목록 개별 선택/Mock 취소와 배치 결과 연결을 구현했다.
- 최종 수량/가격 재검증, 공유 호가 합계 일치, 예약 수량을 통한 신규 배치 중복 차단, 부분 실패/응답 유실/재시작 대조를 보완했다.
- 실제 입력/열린 팝업/모니터 DPI·Steam 서버·설치/배포 검증은 남아 있다. `READ_ONLY_READY`, `LIVE_READY`, `RELEASE_READY`가 아니며 실제 단일 승인 실등록 목표는 차단 상태다.

## 필수 사용자 흐름
1. 공식적인 허용 방식으로 Steam 계정 인증 또는 사용자가 접근을 허용한 읽기 전용 데이터 연결. 로그인 사용자 식별과 장터 쓰기 권한은 별개.
2. 보관함: 게임(APPID) 및 컨텍스트(contextid)별 분류, marketable 품목만 판매 대상으로 제공, tradable과 별도 표시. 인벤토리 대량 페이징·캐시 지원.
3. 품목별 선택·수량 설정, 게임별 전체 선택/해제, 선택된 수량이 실제 보유/판매 가능 수량을 넘지 않도록 검사.
4. 가격 전략 선택: **최근 평균거래가**(집계 구간/거래량 가중·결측 처리) / **즉시거래가능가 추정**(구매주문 호가 단계별 잔량). 최신 시각·출처·수수료/실수령액 표시.
5. 최종 검토창에서 모든 품목의 개별 단가/수량/수수료·합계 및 수동 가격 수정을 확인. 동일 아이템도 호가 단계에 따라 `3개 × 1000원`, `4개 × 980원` 등 복수 단위로 분리.
6. **최종 버튼 `전체 판매등록` 한 번 → 허용/활성화된 실거래 어댑터가 전체 선택분 등록 요청을 시작.** 개별 품목별 추가 클릭은 요구하지 않음. 서비스가 전체 원자 거래를 제공한다는 가정 금지.
7. 항목별 `전송 중/제출됨/승인 대기/게시됨/실패/상태 불명`을 표시. Steam Guard가 필요하면 공식 폰 앱에서 사용자가 승인. 재조회해서 실제 게시 여부 확인.
8. `판매 중` 목록에서 등록 현황과 가격 대비, 개별/다중 취소 계획·검토·결과를 제공. 비허가 쓰기 방식의 취소/재등록은 실제 활성화하지 않음.

## 즉시거래가능가 관련 사실성
- 보여주는 구매주문 수량/가격 단계는 **등록 제안/예상 시나리오**이지 실제 구매주문 체결 확약이 아님. Steam 주문 매칭 우선순위, 국가별 통화·수수료, 시세 지연에 따라 실결과가 달라질 수 있음.
- 각 가격은 **판매자 수령액**인지 **구매자 지불액**인지 라벨을 명확히 하고 서로 변환 시 통화 최소단위와 반올림을 적용.
- 구매주문 수량이 부족하면 일부만 추정하고 나머지는 `즉시 판매 추정 불가`로 표시. 사용자가 정할 가격과 판매 대기 여부를 따로 선택할 수 있어야 함.

## 사용자에게 보이는 범위
- 게임 선택/검색, 카드+테이블 전환, 필터, 정렬, 선택 바구니, 예상 총액, 수수료, 품목별 단가, 판매 중/진행·히스토리/설정·안전 상태.
- 삭제/취소/가격변경은 실제 등록과 별개 작업으로 확인창을 둠.
- 자동 Steam Guard 승인, 게임/Steam 프로세스에 대한 조작, 인증 우회 없음.

## 릴리스 판정 — 반드시 분리
- `DESIGN_READY`: 화면 명세/디자인 토큰.
- `MOCK_READY`: 실제 클릭 가능한 UI, 계산/배치 상태 머신/테스트, 가짜 데이터.
- `READ_ONLY_READY`: 허용된 실제 읽기·로그인 기능(실제 확인한 범위만).
- `LIVE_INTEGRATION_BLOCKED`: 연동 수단이 정책·권한상 확보되지 않음.
- `LIVE_READY`: 허용된 쓰기 연동으로 실등록/취소/승인 대기/재조회가 별도로 검증됨.
- `RELEASE_READY`: 위 범위, 보안/접근성/설치/QA 판정을 README와 실제 UI에 투명하게 표기.
